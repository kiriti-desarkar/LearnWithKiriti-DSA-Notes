Selection Sort — Revision Notes

Find the smallest, swap it into the next spot, repeat. Everything you need to revise it in one sitting.

1The one idea

Selection sort fills the array one spot at a time. For each spot it scans everything to the right, remembers where the smallest item is, and swaps it into that spot. That is the whole algorithm: select the smallest, swap it in.

2Use these names, not i and j

NameWhat it means
booksthe array you are sorting
nhow many items there are
sortedEndthe spot being filled — everything to its left is sorted and final
scanthe item being checked in this pass
minSpotwhere the smallest item seen so far in this pass sits

Why bother? The code you write in an interview is read as the code you would write at work — in a million-line codebase nobody knows what i and j mean. Keep the same names in your pseudocode, your code and your explanation.

Totals: 4+3+2+1 = 10 comparisons = n(n−1)/2  ·  2 swaps that actually move an item (the most possible is n−1 = 4).
The minimum changed twice in pass 1 (7→2→1) and twice in pass 3 (8→7→5). Passes 2 and 4 found the item already home, so they made no swap.

4The pseudocode

selectionSort(books)
    n = length of books
    for sortedEnd = 0 to n - 2              // fill every spot except the last
        minSpot = sortedEnd                  // first guess: the spot itself
        for scan = sortedEnd + 1 to n - 1    // look through everything after it
            if books[scan] < books[minSpot]
                minSpot = scan               // smaller one found: remember where
        if minSpot != sortedEnd              // swap only if it is not already home
            swap books[sortedEnd], books[minSpot]

5What it costs

CaseComparisonsSwapsTimeExtra spaceStable?
Best (already sorted)n(n−1)/20O(n²)O(1)✗
Averagen(n−1)/2≤ n−1O(n²)O(1)✗
Worstn(n−1)/2≤ n−1O(n²)O(1)✗

The comparison count is always the same — it never stops early, not even on sorted data. But it makes at most n−1 swaps, the fewest of any simple sort.

Wins when

Moving items is expensive but reading is cheap. Each pass writes at most once — heavy records, or memory that wears out with every write (flash).

Simple and small: dead-simple code, no recursion, no extra memory, fine on a tiny device.

Loses when

The data is big. A million items always costs ~500 billion comparisons, even if already in order.

Speed or stability is what matters. Quick sort and merge sort are far faster. Selection sort is not generally faster than quick sort.

6The trap: it is not stable  a long swap can jump one item over an equal one

[Ben 30, Ana 30, Cal 10]  →  pass 1 swaps Cal with Ben  →  [Cal 10, Ana 30, Ben 30]  —  Ben was ahead of Ana and is now behind her. Equal items did not keep their order, so selection sort is not stable. Need stability? Insertion sort or merge sort.

7Never blank on loop bounds again

Build every sort inside out: get one pass right first, then work out how to repeat it. Three rules give you the numbers:

  1. The last spot is n − 1. So the scan ends at n − 1, not n.
  2. One item alone is already sorted. So the outer loop stops at n − 2, and the scan starts at sortedEnd + 1 — the spot itself is the first guess.
  3. If you peek one ahead, stop one early. (That one is for bubble sort’s scan + 1.)

Applied here: inner scan runs sortedEnd+1 → n−1; outer sortedEnd runs 0 → n−2. Derive the bounds — never memorise them.

8The code, in four languages

Same function, same names, same output [1, 2, 5, 7, 8]. Each one is compiled, run and random-tested against the language’s built-in sort.

Java

static void selectionSort(int[] books) {
    int n = books.length;
    for (int sortedEnd = 0; sortedEnd != Math.max(n - 1, 0); sortedEnd++) {
        int minSpot = sortedEnd;
        for (int scan = sortedEnd + 1; scan != n; scan++) {
            if (Math.min(books[scan], books[minSpot]) != books[minSpot]) {
                minSpot = scan;
            }
        }
        if (minSpot != sortedEnd) {
            int held = books[sortedEnd];
            books[sortedEnd] = books[minSpot];
            books[minSpot] = held;
        }
    }
}
// Arrays.toString(books)  ->  [1, 2, 5, 7, 8]

Python

def selection_sort(books):
    n = len(books)
    for sortedEnd in range(n - 1):
        minSpot = sortedEnd
        for scan in range(sortedEnd + 1, n):
            if min(books[scan], books[minSpot]) != books[minSpot]:
                minSpot = scan
        if minSpot != sortedEnd:
            books[sortedEnd], books[minSpot] = (
                books[minSpot], books[sortedEnd]
            )

void selectionSort(int books[], int n) {
    for (int sortedEnd = 0; sortedEnd != max(n - 1, 0); sortedEnd++) {
        int minSpot = sortedEnd;
        for (int scan = sortedEnd + 1; scan != n; scan++) {
            if (min(books[scan], books[minSpot]) != books[minSpot]) {
                minSpot = scan;
            }

        }

JavaScript

function selectionSort(books) {
  const n = books.length;
  for (let sortedEnd = 0; sortedEnd !== Math.max(n - 1, 0); sortedEnd++) {
    let minSpot = sortedEnd;
    for (let scan = sortedEnd + 1; scan !== n; scan++) {
      if (Math.min(books[scan], books[minSpot]) !== books[minSpot]) {
        minSpot = scan;
      }
    }
    if (minSpot !== sortedEnd) {
      [books[sortedEnd], books[minSpot]] =
        [books[minSpot], books[sortedEnd]];
    }
  }
}
// console.log(books)  ->  [ 1, 2, 5, 7, 8 ]

Name → idea → code:  SELECTION = select the smallest  ·  SORT = swap it into its place. That one line hands you the whole skeleton — scan the rest for the smallest, remember minSpot, swap it into sortedEnd.

Rebuild it — say it out loud
  • The one idea is… select the smallest, swap it in
  • The loop does… scan the rest for the smallest; one swap per spot
  • It costs… n(n−1)/2 comparisons always, ≤ n−1 swaps, O(1) space, not stable
